# EPUB Store 접합 검사

`python3 Tests/checks/epub-product/run.py --output <storage-route의 외장 출력 폴더>`로 실행한다. 빌드·CFFIXED_USER_HOME·TMPDIR·자체 Vault·선택 Files·영수증은 지정 폴더의 새 실행 디렉터리에만 둔다. HOME은 변경하지 않으며 실행으로 tracked 결과를 갱신하지 않는다.

실제 CanvasStore, 기존 생성/선택/시도 원장, 모듈의 native NSTextView 선택, CanvasDocumentFiles와 Node ObsidianVault의 파일 처리 코드를 사용한다. Node는 기존 test-guard의 네트워크 차단 아래 stdio로만 호출한다. 기본 정상 앱 sentinel과 입력 SHA는 실행 전후 대조한다. 파일 교환 helper의 PID 종료도 확인한다.

2026-10-29 `native-d0ce2bf8-98cd-46bd-833e-b189b233e8e8` 실행은 부모54조건·별도 프로세스5회(각3개 관측)를 통과했다. 이는 기능 수나 동등성 수치가 아니다. 자체2장 EPUB 선택→stable ID→생성/전체GET→카드→전체 Files/새 Store, 외부 Markdown CAS 역수신, 정확 인용 복귀, 미지원/다른SHA 거부, 페이지/연결 ABA, 404와 연결실패 구분, ACK 미확인 후 명시 GET, nil-base 기존 노트 덮어쓰기 거부, 실제 보존형409의 비교/명시 선택/전체GET을 확인했다. 동일 archive 원본은 끝까지 불변이었다.

제품 Store·Files 코드는 주입하지 않는다. 네트워크 callback에는 자체 Vault 결과/의도적 ACK·연결실패를 전달한다. **실제 HTTP/200 ACK 유실의 네트워크 관측, SwiftUI 화면, iOS 최종 SDK, 설치·원앱 iPad·Pencil 수용은 아니다.** Native compile은 macOS27 SDK를 사용한다. Workspace는 별도 syntax parse이며 전체 iOS Store/UI 검사는 부모의 최종 결합에서 한 번 수행한다.

현재 e554 모듈 수리는 소비했으나 Nash 재검수 대기다. raw endpoint 소유와 기존 복구 envelope의 명시 EPUB 구분은 부모 계약 결정 대기다. 스키마 수용·배포·전체 EPUB 완료는 false다. `preflight.py`의 이전 raw 파일10검사는 실제 Store/HTTP 검사와 별개이며 동일 서버 바이트 근거를 재사용한다. 모듈44/25·기존 PDF 전체 검사는 다시 돌리지 않는다.
