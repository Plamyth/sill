# Host microphone backend candidate

## 초기 준비 watchdog 회귀

Root의 2026-11-05 결정에 따라 Host 초기 준비는 10초 미만의 유한 budget을 사용한다. 실제 Host241 로그의 준비 지연 7.524205875초를 허용하며, 별도 iPad 담당이 client start 대기를 12초로 맞춘다. 공통 wire timeout이나 protocol 필드는 바꾸지 않는다. active 진입 시 PCM idle 기준을 재설정하고 이후 2초 초과 idle 보호를 유지한다. owner·현재 connection·닫힌 render gate·출력 유효성 검사는 그대로 유지한다. watchdog tick 전에 준비 콜백이 반환되어도 10초 경계에서 active로 전환하지 않고 반환 resource를 정리한다.

`python3 -B Tests/checks/microphone-uplink/run.py ROOT OUTPUT --receiver-only`는 기존 `Fixture(delayed: true)`, fake clock, continuation과 production receiver/grant/HAL 소스, cleanup 진입점을 재사용한다. 7.524초 준비 성공, 10초 직전·경계, tick 없는 늦은 완료, 준비 중 취소·grant/connection/render 상실·clock 역행과 active idle을 검사한다. 관련 mutation도 실제 컴파일·실행한다. 외부 Network/HAL seam은 inert이며 실제 CoreAudio 호출·capture는 없다.

이 선택은 server/catalog/원본 owner 통합을 제외한다. 기존 전체 fixture는 기준 소스에서 protocol 추출 목록이 뒤처져 컴파일되지 않았으며 이 선택의 성공으로 전체 검사를 통과했다고 보지 않는다. 실제 privacy/proof 손실과 await 중 membership 교체는 별도 기존 `Tests/checks/native-mic-forwarding-proof/run.py`의 production 추출 회귀로 대조한다. 실기기·실제 capture·HAL 지연 원인·서명·Host 설치 수용은 Root의 후속 검증이다.

This unit implements fork kinds 204 control, 205 state, 206 frame, and 207 receipt. It provides host transport and an owner-bound public AUAudioUnit output sink. Native microphone capture, AVAudioSession arbitration, client UI, an original-call owner adapter, and physical audio acceptance remain open. The public initializer's `microphoneOwner` defaults to nil. The menu bar host now supplies SillVirtualMicrophoneOwner for explicit Mac default-input routing through BlackHole2ch. A CLI or other host with no provider advertises no capability. An injected valid owner can advertise protocol availability; native unit construction or format failure must refuse the explicit start. Public API availability is not proof that a particular HAL bridge, driver, endpoint or call works.

`HostLocalOwnerGrant` is a host-local object with synchronous revocation. It binds an opaque destination and capability, authenticated connection identity, source, input generation, committed video epoch, paired fingerprint, original owner, call generation, exact virtual output/input UID and plugin, existing channel mapping, and monotonic expiry. The future original owner must establish that mapping and revoke the object synchronously on call or input change. Neither a process device list nor thread-scoped appendAudio supplies an exact call writer fence. A remote packet, paired name, installed driver, or compile result cannot create authority.

The receiver has off, preparing, active, retiring, and cleanupFailed states. Its finite action table keeps replay outcomes without eviction. It reserves one stop outcome and refuses exhausted actions or lease serials. A stopped preparation still cleans its own returned resource. Cleanup failure retains that resource, closes frame/render admission, and blocks new starts without retry. An old exact stop can retrieve its terminal outcome after the source changes. A stop with nil grantID reconciles the original start requestID, even before start arrives or while preparation or its enabled reply is pending. It records a bounded tombstone before ordinary replay/conflict handling. Later starts with that same ID cannot allocate a sink. On a full ingress queue the same-ID cancellation replaces its pending start. An unmatched overflowing cancellation quarantines and cancels its peer; the queued and later starts cannot reach the receiver. The Mac General settings call the host-local `retryCleanup(grantID:)` with the retained lease ID. No cleanup wire operation or capability field was added. A reconnected peer cannot bypass cleanup, and a cleanup action never starts capture. Remote duplicate stop does not trigger a cleanup retry or allocate another effect.

PCM is 48 kHz mono signed 16-bit little endian, with 1 through 960 frames per packet. Its 113-byte binary header has version, format, six UUIDs, a tagged source, sequence, and frame count. The decoder checks lengths before sample storage. Sequence gaps over 4096, replay, mismatched scope/grant, and application queue residence over 160 ms are refused. The application ingress has eight control slots and a six-frame ordered queue, with one scheduled actor drain before the ordinary per-message Task path. The render buffer also holds at most six packets: a five-packet 100 ms input burst can start playout up to 60 ms after ingress and finish at the 160 ms application-residence boundary. PCM is decoded before acquiring its state lock, which only protects the bounded sample copy and ring pointers. The callback uses a nonblocking lock and may emit silence on contention. Overflow discards the oldest packet; ingress and render keep saturating local drop counters. Expired packets are discarded before rendering. Stop or revocation clears pending audio. These limits do not bound TCP/OS queues or measure end-to-end latency. Wire receipts still report admission and render counters plus application queue age, not the new local drop counters.

Only currently paired TLS fingerprints on nonsynthetic hosts can reach the microphone path. Pair removal closes its named fingerprint's gate synchronously before asynchronous session teardown. Plain TCP and unpaired TLS cannot grant microphone access. Source changes, same-source pipeline restarts, epoch invalidation, disconnect, owner revocation, expiry, idle ingress, and runtime endpoint changes close admission. Watchdogs begin only after an explicit accepted start. The active response opens sample admission at the fixed NWConnection send boundary under the render and owner gates; a queued response cannot reopen a closed lease.

The output adapter uses public HALOutput with input bus 1 disabled. It resolves the granted output and input UIDs, verifies virtual transport, plugin identity, live state, existing rate and channel counts, sets the owned unit's CurrentDevice, reads it back, and verifies the client format before initialization/start. The HAL sink writes only its owned unit. The menu bar owner separately leases and conditionally restores the default input. Neither changes nominal rate, buffers, mute, volume, hog mode, aggregate devices, or an application call. Plugin identity comes from official bundle translation and exact plugin device-list membership, including when the device owner is the system object. An unsupported endpoint or format refuses; it never selects a speaker fallback.

The public AUAudioUnit HALOutput path replaces the manually retained C refCon path. Its copied outputProvider block captures only the render context strongly. It does not capture the unit, facade or worker. PCM storage remains alive if a callback copy outlives successful cleanup, and the closed render gate produces silence. No manual callback memory release or instantaneous in-flight counter is used as a lifetime proof. Hardware create/configure/allocate/start/stop/deallocate and object queries are confined to one private worker actor. The MainActor facade uses Receiver's existing watchdog and at most one in-flight validation, returning cached validity. It closes render admission before awaiting cleanup. A stalled hardware operation cannot hold MainActor, but may leave the owned resource retiring until the driver returns.

The worker uses one owned-unit lifecycle. Failed stop or deallocation readbacks retain the unit and provider and return cleanupFailed through the receiver. Repeated ordinary close does not repeat hardware effects. Explicit retry operates only on that same unit. Successful stop and resource release precede provider/unit release. Public object readbacks describe the owned unit, not physical quiescence or silence in another application. Actual HAL bridge support, callback timing, loopback isolation, original-call consumption and audible behavior remain unaccepted. The menu bar host has an explicit Mac-input provider; an exact Codex call owner remains a separate gate. No native runtime path is executed in these inert tests.

## Parent execution

Run only in the parent's approved isolated Mini RAM/SDK environment:

```text
python3 -B Tests/checks/microphone-uplink/run.py ROOT OUTPUT
```

ROOT is this exact accepted Git worktree or separately receipted source. OUTPUT must be outside ROOT. The driver has a 660-second total budget and 90 seconds per child. It compiles a fake Network module, real protocol declarations, the real receiver/grant/ingress/HAL adapter, exact Coordinator/Server/RemoteAccess boundary bodies, and synthetic CoreAudio buffers. Object queries and output units use injected inert seams; no native AudioUnit or device function is executed. The native AUAudioUnit adapter is compiled with the production source but never constructed by this fixture. The driver compiles the declared source mutants, including weak block capture, MainActor hardware work and unbounded validation. A compile failure never counts as a caught mutant.

The driver writes each command's combined diagnostics, generated fixture files, source and extraction hashes, process/reaping records, assertion count, mutant results, and `result.json`. It prints one `RESULT_JSON` line. On timeout it terminates/reaps the child and saves diagnostics before returning. The parent must preserve these results before RAM cleanup and separately receipt source identity, SDK compilation, independent review, and cleanup. Do not substitute this fixture for whole-product SDK checks. Existing presentation/native-input fixtures remain separate regression gates.

Python AST parsing, exact fixture generation, unique mutation anchors and diff checks precede parent runtime execution. Exact host compilation, fake runtime, mutation and review receipts are recorded outside this worktree. Device/audio behavior and original-owner Result acceptance remain separate gates.
