# Pencil 텍스트 교정 적용 범위

원문·연결 문단·노드의 편집 가능한 텍스트는 동일 VaultMarkdownEditor를 사용한다. 기본 입력은 iOS Scribble와 UITextView 편집메뉴다. 펜 교정을 켜면 지그재그는 글자 삭제, 위쪽 획은 같은 줄의 공백 합치기, 아래쪽 획은 글자 사이 나누기를 처리한다. 일반 터치는 기존 선택·스크롤을 사용한다.

합치기는 실제 공백 영역에서 연속 U+0020만 제거한다. 줄바꿈·문단·탭·Unicode 공백과 줄 끝의 Markdown hard break는 건드리지 않는다. 나누기는 실제 caret 가까이에서 글자 사이에 공백 하나를 추가한다. 글자 중앙·다른 줄·멀리 떨어진 caret으로 추정해 적용하지 않는다. 삭제는 기존 글자 중심 mapping을 유지한다.

글자를 선택한 뒤 도구 막대의 선택 글자 교정이나 네이티브 편집메뉴의 선택 글자 교정을 연다. 입력창은 원래 선택한 글자를 표시한다. 직접 입력하거나 OS가 지원하는 손글씨 입력을 사용한 뒤 적용을 눌러야 선택 글자만 바뀐다. 취소·빈 입력·원문과 같은 입력은 변경하지 않는다. MyScript 후보나 AI가 생성한 인식 후보를 제공하지 않는다.

각 교정은 정확한 원문 UTF8·편집 세션·선택 snapshot을 사용한다. 그리는 동안 또는 입력창을 연 뒤 원문·선택·세션이 달라지거나 IME·Scribble가 시작되면 이전 요청을 적용하지 않는다. 이전 요청의 취소·중복 확정은 새 요청을 바꾸지 않는다. 교정 입력창이 열린 동안 기존 inputBusy로 저장과 문단 전환을 막는다. UIKit replace로 Undo/Redo에 연결하며 Store의 SHA CAS·장면·노드 기대 상태·복구 기록·저장·재열기 경로를 그대로 사용한다.

원본 PKDrawing과 sourceStrokeIds는 보존한다. 원시 필기에서 글자별 획을 자동 정렬·재배치하지 않는다. 언어별 OS 손글씨 입력과 Pencil 센서 응답은 실제 사람 입력으로 별도 수용해야 한다. 모델 검사·UIKit replay·격리 Obsidian 왕복·실제 Pencil·설치 수용은 각각 구분한다. 이번 구현 자식은 검사 소스만 추가하며 실제 실행과 독립 검수는 부모가 exact commit에서 수행한다.
