## Admission contract

`SourceRequest` keeps the synthesized `StreamSource` at the kind 6 JSON root. `selectionOrigin` is human or automatic. `selectionRevision` is required for a modern automatic packet. Any present malformed metadata fails decoding without retrying as legacy. `WindowList.selectionRevision` is optional for old hosts and clients.

`StreamCoordinator.pickSequence` remains the single host ordering counter. The wire CAS revision combines its host launch ID and this dedicated intent sequence. It does not use `inputGeneration`. The settled sequence records completion, not a second admission order. Each valid explicit source, same-source choice, None, monitor selection, CLI pick or launch reserves the next sequence before suspension. A successful automatic admission consumes one exact revision in eligible idle or internal-restart state. The current admitted peer is tracked so its disconnection cancels only work it owns. Bad metadata and peers absent from `SourceInputFence` cannot reserve an intent.

Connection joins, Hello input negotiation, disconnects, client counts and message admission use one network-to-main `CoordinatorIngress` stream. Its consumer invokes synchronous admission closures in submission order. It does not await capture execution. Source execution tasks and the single existing replay slot retain sequence, origin and peer. Pending launch completion uses the original ticket. Inventory refresh, audio revocation, capture stops, staging, capture startup and pipeline fallback recheck the ticket. `startPipeline` checks after capture startup before active source and epoch changes. It captures a SourcePublicationAdmission and passes it to the actual queued commitVideo. Publication holds that admission lock through the catalog sends and keyframe request. Reserving or cancelling a source intent invalidates the previous admission under the same lock before advancing the host sequence. A publication already holding the lock finishes before newer admission completes; an invalidated publication cannot begin. A superseded attempt can stop its own capture because `switching` still excludes the next pipeline until it returns.

Unannotated legacy packets keep unknown provenance. They drop during ordinary transitions, for the same restarting source, or against unsettled intent. They do not acquire human priority during replay. Old hosts ignore the new metadata and cannot enforce CAS. Updated clients still cancel local tickets and send peer-bound automatic packets through `SessionLink`. Full provenance for unchanged legacy endpoints is not provided.

The client synchronously cancels resume and delayed tickets at every explicit entry point, including a refused monitor choice. An unfenced handover creates a distinct connection opportunity containing intent version, new peer and host launch, with no inherited revision. Its first current-peer catalog creates the immutable request ticket with that catalog revision. Explicit intent cancels the opportunity. An old ticket is never rebased. Explicit intent also cancels an already queued automatic SessionLink.Submission. A delayed closed-window fallback checks its original revision against the currently observed revision before any source-change hook and stores one immutable ticket; later idle catalogs cannot replace its revision or bypass its delay. First-idle opportunities are consumed once. A new connection opportunity cannot revive a still pending or failed explicit choice, including None. A successful source, monitor or launch catalog with a changed revision and a new valid video epoch creates a new closed-window recovery opportunity. None and failed choices do not. A changed admission revision with the previous video epoch is not a success acknowledgment. An old host has no revision acknowledgment, so its matching active catalog provides only the documented weaker local behavior.
