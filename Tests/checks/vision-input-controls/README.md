# Source coupled gesture lifecycle checks

`run.py WORKTREE FRESH_OUTPUT` runs this worktree's extracted input controls and pointer checks with a 600 second suite deadline. Each command receives an execution timeout of at most 90 seconds, checked between process queries, with 15 seconds reserved at the suite deadline for cleanup. Keep output in the development archive path returned by `storage-route` for CCR-Vision. Output paths cannot contain whitespace because `ps` does not preserve argument quoting. Each command records its arguments, exit status, process cleanup, and log. `manifest-before.json` and `manifest-after.json` bind production Swift and project inputs, harness inputs, emitted files, and extracted closures by SHA256.

Children receive `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` through their own environment. The runner does not change the parent environment or global `xcode-select`. The result records the Git HEAD and tree, global selection, child compiler path, SDK path, and Swift version.

Commands, process queries, cleanup polling, and final leader waits share the absolute suite deadline. Each query receives at most five seconds and at most the remaining budget. Standalone cleanup has one shared 15-second budget. Budget exhaustion leaves cleanup unverified. A virtual-clock regression reproduces five slow queries consuming 20 seconds in the old runner and verifies that the fourth query stops at the remaining three seconds.

The runner observes process groups and descendants while commands run. It stores PID, start time, and full command as process identity. A detached compiler that has already reparented can also qualify through an exact `-o`, `-module-cache-path`, or `-emit-module-path` argument beneath the fresh output directory. That discovery accepts only named compiler executables in the pinned Xcode toolchain. Shared path prefixes, source arguments, and unrelated executables do not qualify. Cleanup rechecks identities before signaling and verifies both the group and detached processes afterward. A failed or incomplete `ps` query records unknown cleanup and fails the command. `childrenReaped` requires a reaped command leader and verified absence of all live owned processes. It does not claim to wait on reparented children. Zombies are not live processes.

`extract.py` requires unique source markers and inserts five complete, unchanged closures from `VisionSpatialInput.swift` into `Lifecycle.swift`. Optional contact, magnification, and rotation DTOs provide only callback values. The adapter stores the View revision and admission state. Actual production `VisionInputSession`, `VisionPointer`, transport methods, and release debt implement gesture behavior. The display adapter records steps and target IDs through the production `VisionDisplaySelection.adjacentCommand`. It does not execute the host selection transport or its release fence.

`LifecycleTests.swift` invokes those closures through an inert scheduler. It covers click, scroll, hold, drag, magnification arbitration, contact tails, duplicate ends, recognition reset, disappearance, admission and stale callbacks across geometry, source and revision changes. Cancellation must avoid phantom input and balance transmitted releases. Synthetic cancellation orders do not have to produce a click.

One pinch clicks. Two quick pinches double click. A stationary hold produces a right click on release. Movement scrolls both axes, including movement after a hold without modifiers. A held modifier permits the existing optional drag. Magnification changes the local viewport. Rotation selects one adjacent Mac monitor only on completion at an absolute terminal angle of at least 25 degrees. Positive angles select the next monitor and negative angles select the previous monitor. Rotation never changes remote playback gain. Explicit volume controls retain their gain path.

Rotation checks cover both directions, the exact threshold, large angles, terminal angle changes, duplicate ends, cancellation, invalid angle, time, and anchor values, and out of order callbacks. A zoom of at least eight percent suppresses rotation for the rest of the gesture, including a return to its initial scale. Pointer and scroll releases precede rotation selection. Missing, empty, single, late, or changed monitor inventories reject selection. Tests also retire the original rotation across input binding, source, peer, window, admission, display token, and client changes. A replacement client with the same binding, source, and display token still requires a fresh gesture.

Five compiled mutants exercise callback dispatch order, terminal cleanup, disappearance, recognition reset, and revision capture. Each must fail at its named behavioral witness. The existing six transport mutants remain available to the remote runner; this local suite does not compile them again. `test_runner.py` checks local and remote compile lists and all remote mutant substitutions without running Mini or creating a RAM disk. It reproduces leader exit and timeout with normal and `start_new_session` descendants, including a detached child observed after reparenting to PID 1. It verifies unrelated children survive, compiler output binding rejects false positives, changed identities receive no signal, and failed process queries cannot claim cleanup. Set `VISION_RUNNER_TEST_OUTPUT` to a fresh archive directory for standalone tests. The full runner sets it for its child tests. Detached witness receipts are written there.

This fixture does not prove SwiftUI recognizer scheduling, real gesture values, visionOS SDK compilation, device behavior or host delivery. The remote entry point is retained for compatibility; this unit validates its command inputs only. Signed SDK source comparison and independent review belong to the original owner after this writer releases the worktree.
