# 공통 호스트의 Native Dock

이 변경은 공통 호스트 `068be8f4a50444716aefe86347e7ae5dfa947f5d`에 iPad 후보 `429a3719a4203d3c1e605c0085f79883bf365238`의 Dock 범위만 옮긴다. iPad의 다른 호스트·오디오·권한 변경을 가져오지 않는다.

Dock 요청은 kind 215, 응답은 216이다. Vision의 기존 Sentry 213/214와 catalog 212는 재사용하지 않는다. iPad 담당과 215/216을 조율했으며 Android 담당은 이 번호를 사용하는 변경이 없다고 확인했다. 기존 `WindowList.dockApps`는 유지하고 새 `dock`은 선택 필드로 보낸다. 구버전 클라이언트는 새 필드를 무시하며 새 클라이언트는 필드가 없으면 호스트 미지원 상태를 유지한다.

Dock 액션은 연결의 입력 사용권, 준비 상태, 암호화된 경로와 실제 페어링 지문을 모두 확인해야 실행된다. 요청 크기는 4096바이트이며 연결마다 초당 8건을 넘으면 실행하지 않는다. 연결 종료 시 열린 메뉴의 해당 소유자만 정리한다.

`.press`와 `.choose`는 ingress에서 소스 선택 순번을 받는다. 실제 Dock AX 액션 전에 기존 `select(.none)`으로 캡처·입력·원격 오디오를 종료하고 마이크의 종료 상태를 확인한다. 더 최신 선택이 도착하면 기존 Dock 액션은 실행하지 않으며 최신 요청 하나를 전환 뒤 처리한다. 연결·페어링·세대가 바뀐 뒤 지연된 결과로 창을 선택하지 않는다.

기존 명시적 선택이 데스크톱이었다면 같은 선택을 복원한다. 창 송출이었다면 실제 전경 앱의 키보드 포커스가 확인된 유일한 창만 선택한다. 앱의 첫 창이나 새 데스크톱 전체를 자동 대체값으로 선택하지 않는다. 2초 안에 대상 창을 확인하지 못하면 해당 요청의 오류 안내와 정상 창 선택 UI로 돌아간다.

생산 리더와 호스트 함수를 비활성 AX·네트워크·오디오 모형으로 실행하는 검사는 다음 명령을 사용한다. 저장 위치는 `storage-route`로 검증된 개발 증거 경로를 넘긴다.

```sh
python3 -B Tests/checks/native-dock/run.py ABSOLUTE_WORKTREE ROUTED_EVIDENCE_DIRECTORY
```

이 검사는 실제 Dock 조회·AX 액션·기기 UI·오디오/HAL을 실행하지 않는다. SDK 빌드, 독립 검수, 서명 후보, 설치된 앱, 실제 원격 기기 동작은 각각 별도 증거다. 현재 사용 중인 Mac의 설치·재시작이나 실제 Dock 클릭을 이 검사 결과만으로 완료 처리하지 않는다.
