# 소유 Mac의 공개 연결 설정을 Vision 앱에 포함하기

이 절차는 승인된 앱 설치 과정에서 공개 Mac ID와 TLS 지문을 공급한다. 최초 기기 등록은 호스트가 별도로 실제 소유자의 Tailscale 노드를 검증한 뒤 허용한다.

## 필요한 입력

기존에 인증된 Mac의 공개 설정 파일과 검증 영수증의 SHA-256이 필요하다. 파일 이름은 `CCR-OwnerMacBootstrap.json`으로 앱에 들어간다. 파일에는 `schema`, `macID`, `fingerprint`, `addresses`, `remotePort`만 포함한다. 개인키, 인식 키, bearer token은 포함하지 않는다.

공개 설정의 해시는 출처 확인을 대신하지 않는다. 설치 담당은 현재 정식 호스트의 TLS 지문과 대조한 설정을 사용한다. 실제 기기의 기존 등록이나 Mac의 키를 초기화하지 않는다.

## 서명 전에 포함하기

기존 `SillVision` 빌드 명령에 다음 두 설정을 추가한다. 경로와 해시는 검증 영수증의 정확한 값으로 지정한다.

```text
CCR_OWNER_MAC_BOOTSTRAP_INPUT=/absolute/path/to/public-profile.json
CCR_OWNER_MAC_BOOTSTRAP_SHA256=verified-sha256
```

프로젝트의 `소유 Mac 공개 연결 설정` 빌드 단계가 공개 필드와 주소를 검사하고 앱 리소스에 복사한다. Xcode는 이 단계 이후 기존 팀과 bundle ID로 앱에 서명한다. 서명 후에는 앱 안의 파일을 수정하지 않는다.

설정을 지정하지 않은 새 빌드는 공개 연결 설정을 포함하지 않는다. 기존 빌드에 다른 설정이 남아 있으면 복사를 거절하므로 새 빌드 출력 경로를 사용한다. 프로젝트 소스와 Git에는 실제 개인 Mac의 공개 설정을 저장하지 않는다.

## 확인하기

빌드한 앱 안의 `CCR-OwnerMacBootstrap.json` 해시가 검증한 입력과 같은지 확인한다. 실제 설치 후보는 전체 앱의 엄격한 서명 검사와 기존 bundle ID·서명 팀 대조도 통과해야 한다.

리소스 복사, SDK 빌드, 앱 서명, 설치와 실제 최초 연결은 각각 별도의 검증 상태다. 공개 파일이 들어갔다는 사실만으로 기기 등록이나 원격 제어를 완료했다고 표시하지 않는다.

## Vision 연결과 취소 경계

기존 저장 정보나 선호 Mac 키가 있으면 최초 등록으로 우회하지 않는다. 원시 저장 키의 존재는 `startRemote`가 읽을 수 없는 기존 기록을 정리하기 전에 고정한다. 최초 빈 저장소에서만 앱에 포함된 공개 설정을 읽는다.

등록 요청은 소유자 전용 TLS 채널에서 한 번 전송한다. 사용자 취소는 전송 허용권을 동기적으로 폐기하고 같은 앱 실행에서 다시 시작하지 않는다. 운영체제 비활성화로 중단한 경우에는 다음 활성화 때만 다시 시도한다. discovery 콜백이나 타이머로 무한 재시도하지 않는다.

응답을 저장하기 전에 비전프로 창의 사용권, 앱과 장면의 활성 상태, 현재 기기 키, 저장소와 다른 연결의 점유를 재검사한다. 정상 응답의 주소를 새로 신뢰하지 않고 앱에 포함된 설정 주소를 사용한다. 이후 정식 세션에서 서명이 확인된 Mac 정보만 주소를 갱신한다.

`Tests/checks/vision-owner-bootstrap/run.py`는 실제 Vision 어댑터, 공통 교환과 연결기를 추출하거나 그대로 컴파일해 I/O 대역에서 실행한다. `project.py`는 프로젝트 재생성 후 운영·격리 테스트 대상 모두의 인증 소스를 확인하고, 공개 설정 공급 단계가 운영 앱에만 들어가는지 확인한다. 기존 저장 신뢰의 비활성화 복구는 별도의 `vision-autoconnect` 검사로 유지한다.


## 자동 등록 세션의 경로

`owner-tailnet-v1`으로 등록한 기록은 정상 `sill/1` 세션도 숫자 Tailscale 주소로 연결한다. 저장된 LAN 주소, DNS 이름과 typed 주소는 지우지 않지만 이 등록 방식의 연결 후보에는 넣지 않는다. 같은 Mac의 Bonjour 행을 눌러도 저장된 Tailscale 주소와 기존 pin을 사용한다. 연결 중 LAN·케이블로 자동 이동하지 않는다.

호스트는 자동 등록 기록을 디스크에서 읽었다는 이유만으로 세션 권한을 주지 않는다. 해당 소켓의 기기 키와 현재 소유자 검증이 끝난 뒤에만 세션을 수용한다. 이 경로는 기존 QR·코드·케이블·iCloud 등록의 주소와 이동 정책을 바꾸지 않는다. Tailscale을 사용할 수 없을 때 새 등록 권한이나 LAN 예외를 만들어 우회하지 않는다.

`Tests/checks/owner-session-routing/run.py`는 실제 저장 연결 후보 식과 home 진입 메서드를 실행해 이 구분을 검사한다. 호스트의 재시작·기기 키·소켓별 권한 검사는 공유 호스트 담당의 별도 계약 검사이며 앱 라우팅 검사로 대신하지 않는다.
