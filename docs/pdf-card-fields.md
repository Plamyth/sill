# PDF 발췌 카드의 제목·인용·메모

951c의 PDF 원문·복구 범위 검수에서 발견한 PDF-CARD-01의 후속 구현이다. 기존 발췌 Markdown을 그림판의 한 노트 카드로 유지한다. 별도 노트 DB, scene 종류, 영구 상태나 의존성을 추가하지 않는다.

카드에는 제목, 선택 당시의 원문 인용, 메모·댓글을 나눠 표시한다. 노트를 열면 제목과 메모를 각각 편집하며, 인용과 PDF 경로·페이지·SHA는 읽기 전용이다. 'PDF 원문 보기 · 출처 검증'은 기존 PDF SHA·textRanges·rect·quote 검증을 사용한다. 'Markdown 원문 편집'으로 문서 전체를 고치는 경로도 유지한다.

원본은 같은 `.md`다. 기존 첫 번째 한 줄 `# 제목`, 기존 인용·원문 링크, `## 메모` 구획과 실제 최상위 출처 fence를 읽는다. 제목·메모 입력은 그 범위만 바꾸고 다른 본문과 provenance를 보존한다. LF·CRLF와 원고의 공백·Unicode를 유지한다. 출처의 정렬된 JSON을 SHA로 비교하므로 Swift 문자열 동등성이 같은 것으로 취급하는 Unicode 조합 차이로 인용 바이트를 교체하지 않는다.

제목은 한 줄이다. `## 메모`와 실제 출처 블록 사이의 내용이 전용 메모 필드다. 출처 뒤에 외부에서 덧붙인 내용은 별도로 표시하고 전체 Markdown에서 편집한다. 일반 제목/인용/메모 구획으로 안전하게 해석할 수 없는 문서는 전체 Markdown 경로로 열며 임의로 구획을 이동하거나 버리지 않는다. 최상위 PDF 출처가 없는 일반 `.md`는 원래 편집기를 사용한다. 손상·중복 출처는 확인 필요 상태로 구별한다.

입력은 기존 `vaultDraft`와 noteRecovery에 보존한다. 현재 입력 session·노트 경로·base SHA·원래 출처가 일치할 때만 필드 변경을 받는다. 기존 Markdown CAS와 별도 GET을 마친 후 같은 node ID의 표시 캐시를 갱신한다. 외부에서 제목·메모를 고치면 같은 파일의 재조회로 돌아오고, 로컬 미저장 입력과 겹치면 기존 보호가 자동 덮어쓰기를 차단한다. 원본 PDF를 수정하지 않는다.

node.text는 제목/인용/메모의 표시 캐시다. 각 항목은 기존512바이트 preview로 제한하며 Markdown/출처 JSON 전체를 카드 표면에 표시하지 않는다. 전체 본문은 기존 원본 노트 참조로 읽는다. 새 저장 schema는 없고 이전 장면도 그대로 읽을 수 있다. 재조회한 카드는 새 projection으로 갱신된다.

게시 후 typed409·미확인 원장은 계속 보호한다. 일반 `.md` 및 PDF 발췌의 명시 복구 resolver는 부모의 별도 후속이며, 이번 필드 구현이 held를 자동 성공 처리하지 않는다. 한 페이지·rotation0 텍스트 발췌 제한도 유지한다.

검증은 실제 UI의 두 Binding 함수를 추출해 기존 Store에 실행하고, Apple SDK에서 전체 CanvasBridge UI를 타입 검사한다. Binding 검사에서 UI State 저장만 메모리 wrapper를 사용하며 화면 렌더링을 실행했다고 주장하지 않는다. 기존 ObsidianVault 모듈을 Mini 한시적 입력에서 표준입출력으로 호출해 실제 CAS·파일 재열기·역방향 수정도 검사한다. 새 서버 listener는 만들지 않는다. 실제 Pencil·기기·Host·사용자 vault·공유 서비스·설치는 수행하지 않는다.

검사 결과는 외장 작업 루트 `evidence/pdf-card-fields/final/result.json`과 `final/runtime.log`에 있다. 필드·실제 UI Binding·실제 파일 CAS/재열기/외부 제목·메모 변경43개, 문단124개, 기존 linked385개가 통과했고 iOS SDK exit0과 전후 입력SHA 일치를 확인했다. Mini 파일검사 사본의 삭제도 확인했다. 화면 렌더링·설치·실제 Pencil 수용은 별도 미검증이다.
